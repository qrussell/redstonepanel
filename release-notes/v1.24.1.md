Three fixes for clusters, mostly mixed Linux and Windows ones.

## Fixed

- **A Windows PC can join a cluster again.** A new Windows install opens only the panel's HTTP port (8080) in Windows Defender Firewall. Joining or creating a cluster turns on HTTPS on port 8443, and 1.24.0 didn't open it, so the master couldn't reach the new node. Creating, joining and leaving a cluster now update the panel's firewall rule, and the panel checks the rule each time it starts.

- **A server created on a node shows straight away.** After you create a server on a node from the master, the server list now asks the node again at once. Before, it could show the master's copy from a few seconds earlier, and the new server appeared only after a reload.

- **The Dashboard and Cluster page load much faster on a master.** Each member used to run the whole port check every time the master asked for its CPU, memory and disk figures. On Windows that takes about 5 seconds, so the page waited for the slowest member. The port check now runs every two minutes as before, but not on every request. The Cluster page also shows the members and their servers first and fills in each machine's figures when they arrive.

## Upgrading an existing panel

Nothing to do. On Windows, click **Update now** on the dashboard, or run `RedstonePanel-1.24.1-x64.msi` below. A Windows node that joined on 1.24.0 opens port 8443 by itself when the panel restarts after the update. If you opened it by hand, nothing changes. Update every member to get the faster Dashboard, since each one answers for itself.

Tested: 1,196 unit tests, including new ones for the firewall rule following cluster changes and for the server list after a change on a node and for the port check staying off the dashboard.

## Installing on Windows

1. Download `RedstonePanel-1.24.1-x64.msi` below and open it. It isn't signed yet, so SmartScreen says **Windows protected your PC**: choose **More info**, then **Run anyway**. Its SHA-256 is in `RedstonePanel-1.24.1-x64.msi.sha256` next to it.
2. Choose where servers, backups and settings are kept. The default is `C:\ProgramData\RedstonePanel`, and the folder's name can't have a space in it.
3. Leave **Open RedstonePanel in my browser** ticked and click **Finish**, then choose your password for **admin**. Or sign in with your own Windows administrator account.

See [On Windows](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md#on-windows) in the manual.

## Installing

RedstonePanel runs on **Ubuntu 24.04, 26.04 and 26.10**, **Debian 13** and **64-bit Raspberry Pi OS** (Raspberry Pi 4 or 5), on x86-64 and ARM64. See [Supported systems](https://github.com/qrussell/redstonepanel#supported-systems). The easiest way to install it, and to get every later version with `apt upgrade`, is the signed **qrussell-repo** apt repository:

```bash
sudo apt install -y curl ca-certificates
curl -fsSL https://qrussell.github.io/qrussell-repo/deb/qrussell-repo.gpg | sudo tee /usr/share/keyrings/qrussell-repo.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/qrussell-repo.gpg] https://qrussell.github.io/qrussell-repo/deb ./" | sudo tee /etc/apt/sources.list.d/qrussell.list
sudo apt update
sudo apt install redstonepanel
```

Or in one line: `curl -fsSL https://raw.githubusercontent.com/qrussell/redstonepanel/main/install.sh | sudo sh`

Then open **http://&lt;server&gt;:8080/** and sign in with a Linux account in the `sudo` group.

To check the repository key before trusting it, `gpg --show-keys /usr/share/keyrings/qrussell-repo.gpg` should show the fingerprint `9994A9EB39EB3C101C949FB2012BA14E0FE3A355`.

Prefer not to add a repository? Download `redstonepanel_1.24.1_all.deb` below and run `sudo apt install ./redstonepanel_1.24.1_all.deb`. You then install each new version the same way.

The [user manual](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md) walks through every feature, with screenshots.

## Upgrading

If you use the qrussell-repo repository:

```bash
sudo apt update && sudo apt upgrade
```

New versions reach the repository within a few hours of their release. Otherwise, install the new .deb as above.

Running servers keep running through the upgrade.
