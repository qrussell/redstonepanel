RedstonePanel now installs on Windows, as a preview: Java servers on one computer, with nearly everything the Linux panel has.

## New

- **A Windows installer.** `RedstonePanel-1.22.0-x64.msi` (below) installs the panel on **Windows 11** and **Windows Server 2022 or 2025**, 64-bit Intel or AMD, with no WSL. Python and everything the panel needs come inside it. Java (Eclipse Temurin) is downloaded the first time a server needs it. Windows 10 installs too but isn't tested.

- **What the preview does on Windows:** Java servers (Vanilla, Paper, Purpur and Fabric) on one computer, with backups and restore, schedules, the console, Live Chat with quick commands, the file manager and its Visual Editor, add-ons, the firewall, performance charts, crash explanations, webhooks, two-factor sign-in, join pages, a servers folder on any drive, and **Found on this computer**.

- **Not on Windows yet:** Bedrock servers, Quilt, Forge and NeoForge, modpacks, memory and CPU limits, off-site backup storage, SFTP, the terminal, clusters and updating from the panel. The panel leaves them out on Windows instead of offering them; they come in 1.23 and 1.24. For them today, use Linux or WSL.

- **Ordinary Windows underneath.** The panel is the service **RedstonePanel**. Each game server is its own service (`minecraft-<name>`) running as its own account that can reach only its own folder. Schedules are tasks under **RedstonePanel** in Task Scheduler, and game ports are rules in the **RedstonePanel** group in Windows Defender Firewall. Game servers and schedules keep running while the panel is stopped, and start with Windows.

- **Found on this computer** (New server) now always shows for an admin, on Linux too: the servers the panel can take over, then what it saw and can't manage with the reason (a running server whose files are missing, a leftover service whose folder is gone, a service that isn't a game server), or that nothing was found.

## Fixed

- **A new server takes the lowest free port.** After removing a server with its files kept, the next new server got the next port up (25566) even though 25565 was free. Now a removed server keeps only its name; restoring it later moves it to a free port if a new server took its own. On Linux too.

## Installing on Windows

1. Download `RedstonePanel-1.22.0-x64.msi` below and open it. The preview isn't signed yet, so SmartScreen says **Windows protected your PC**: choose **More info**, then **Run anyway**. Its SHA-256 is in `RedstonePanel-1.22.0-x64.msi.sha256` next to it.
2. Choose where servers, backups and settings are kept. The default is `C:\ProgramData\RedstonePanel`; the folder's name can't have a space in it.
3. Open **http://localhost:8080** and sign in as **admin** with the password in `first-sign-in.txt` in that folder (open it as an administrator). Change the password under **Users**, then delete the file.

To update later, run the newer installer; your servers, worlds and settings stay. See [On Windows (preview)](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md#on-windows-preview) in the manual.

Tested: GitHub's Windows Server 2022 and 2025 machines install the MSI and run the Windows install test (a Java server from Adoptium's Java: create, start, console, file manager, backups and restore, schedules, a crash and its restart, webhooks, stop and start, the Performance card, join pages, the servers folder and Found servers), then install it again over itself and remove it. The panel was also run on a Windows PC by hand. The 1,019 unit tests pass, and the Linux install and cluster tests are unchanged.

## Installing

RedstonePanel runs on **Ubuntu 24.04, 26.04 and 26.10**, **Debian 13** and **64-bit Raspberry Pi OS** (Raspberry Pi 4 or 5), on x86-64 and ARM64. See [Supported systems](https://github.com/qrussell/redstonepanel#supported-systems). The easiest way to install it, and to get every later version with `apt upgrade`, is the signed **qrussell-repo** apt repository:

```bash
sudo apt install -y curl ca-certificates
curl -fsSL https://qrussell.github.io/qrussell-repo/deb/qrussell-repo.gpg | sudo tee /usr/share/keyrings/qrussell-repo.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/qrussell-repo.gpg] https://qrussell.github.io/qrussell-repo/deb ./" | sudo tee /etc/apt/sources.list.d/qrussell.list
sudo apt update
sudo apt install redstonepanel
```

Or in one line: `curl -fsSL https://raw.githubusercontent.com/qrussell/redstonepanel/main/install.sh | sudo sh`

Then open **http://&lt;server&gt;:8080/** and sign in with a Linux account in the `sudo` group.

To check the repository key before trusting it, `gpg --show-keys /usr/share/keyrings/qrussell-repo.gpg` should show the fingerprint `9994A9EB39EB3C101C949FB2012BA14E0FE3A355`.

Prefer not to add a repository? Download `redstonepanel_1.22.0_all.deb` below and run `sudo apt install ./redstonepanel_1.22.0_all.deb`. You then install each new version the same way.

The [user manual](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md) walks through every feature, with screenshots.

## Upgrading

If you use the qrussell-repo repository:

```bash
sudo apt update && sudo apt upgrade
```

New versions reach the repository within a few hours of their release. Otherwise, install the new .deb as above.

Running servers keep running through the upgrade.
