Run several RedstonePanels from one: clusters let a master panel see and control the game servers on other panels.

## Added

- **Clusters.** Make one panel the **master** and add other panels as **nodes**. The master's **🌐 Cluster** page lists every node's game servers and can start, stop and restart them. Each node keeps its own dashboard, and its game servers keep running if the master is down.
  1. On the master: **Panel Settings → Cluster → Create cluster** (or `sudo redstonepanel cluster create "Home"`). The panel restarts on HTTPS, port 8443.
  2. On the master: **Make a join code** (or `sudo redstonepanel cluster join-code`). Codes work once and expire after an hour.
  3. On each node: paste the code into **Panel Settings → Cluster → Join**, or run `sudo redstonepanel join 'rpjoin1:...'`.
  4. Download the cluster CA from **Panel Settings → Cluster** and import it on your devices once, so browsers trust every panel in the cluster.
- **Limited by design.** On a node, the master can only list game servers, start, stop and restart them, and renew the node's certificate. It can't see or change the node's users or settings, or delete servers. Cluster certificates only cover private addresses and local names (`.lan`, `.local`, `.home.arpa`, `.internal`), so the CA you import can't be used to impersonate other websites.
- **Recovering from a lost master.** Download an encrypted backup from **Panel Settings → Cluster → Backup** (or `sudo redstonepanel cluster backup FILE`) and keep it off the master. `sudo redstonepanel cluster promote FILE` on any other panel makes it the master; nodes accept it at once and refuse the old one from then on.
- **New commands:** `cluster create`, `cluster status`, `cluster join-code`, `cluster backup`, `cluster promote`, `join`, `leave` and `cluster-https` (turns cluster HTTPS back on after `reset-security`). See `man redstonepanel`.
- **The panel's version** is shown next to the title in the header, and returned by `/api/auth/me` as `panel_version`.

## Fixed

- The server action endpoint now only accepts start, stop and restart for the panel's own `minecraft*` units. Before, it passed any action and unit name to `systemctl`.

## Known limitations

- Panels using their own certificate (for example from certbot) can't join a cluster yet.
- The panel doesn't open its HTTPS port in the firewall. If ufw is active, allow port 8443 between the master and its nodes, for example `sudo ufw allow from 192.168.1.0/24 to any port 8443 proto tcp`.

## Upgrading

```bash
sudo apt install ./redstonepanel_1.5.0_all.deb
```

Or `sudo apt update && sudo apt upgrade` if you use the qrussell-repo apt repository. Nothing changes until you create or join a cluster.
