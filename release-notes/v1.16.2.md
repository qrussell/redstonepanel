Kick, ban and unban players from the panel, and a new look: RedstonePanel now has its own logo and a stone-and-redstone theme, in both dark and light.

## Added

- **Kick, ban and unban** in each server's **Configuration → Whitelist & Access**:
  - **Online now** lists the players on the server, each with **Kick** and, on Java, **Ban**. Both take an optional reason the player sees.
  - **Banned** (Java) shows each banned player with the reason, when and who banned them, and **Unban**. Type a name to ban someone who isn't online.
  - Players turned away for a ban get **Unban**, and each **Access log** row has **Kick** while that player is online and, on Java, **Ban**.
  - A running server is told through its console (Java over RCON, Bedrock through `screen`). On a stopped Java server the panel edits `banned-players.json` directly. A running Java server without RCON is refused rather than having its file edited, because the server would overwrite the change.
  - **Bedrock has no ban list**, so it gets kick only: keep someone out with the allowlist.
  - Bans are by name and UUID, never by IP address. Every action goes to the activity log with who did it. Anyone who may manage the server can use them, and on a cluster they work from the master.
- **A new look.** RedstonePanel has its own logo: an "R" traced as a powered circuit. It's in the sidebar, on the sign-in page and in the browser tab, and there are icons for adding the panel to a phone's home screen. The theme uses warm stone greys with redstone-red accents, glowing focus rings, status lamps and usage bars, in both the dark and the light theme.

## Changed

- **Redstone Red is the default accent palette** (Settings ⚙️ → Accent Palette). If you picked a palette before, the panel keeps it.
- **Stop** is an outlined red button, so it no longer looks like **Restart**. Stopped servers show a grey lamp instead of a red one.

## Fixed

- Building the .deb on Windows corrupted PNG images: the build stripped carriage returns from every file, including binary ones. It now only touches text files.

## Upgrading an existing panel

Nothing to do. Reload the panel in your browser after the upgrade to see the new look. Kick and ban on a running Java server use RCON. If a server doesn't have it yet, the panel says so: open its **Live Chat** once and the panel sets RCON up.

## Installing

RedstonePanel runs on **Ubuntu 24.04 and 25.04**. The easiest way to install it, and to get every later version with `apt upgrade`, is the signed **qrussell-repo** apt repository:

```bash
sudo apt install -y curl ca-certificates
curl -fsSL https://qrussell.github.io/qrussell-repo/deb/qrussell-repo.gpg | sudo tee /usr/share/keyrings/qrussell-repo.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/qrussell-repo.gpg] https://qrussell.github.io/qrussell-repo/deb ./" | sudo tee /etc/apt/sources.list.d/qrussell.list
sudo apt update
sudo apt install redstonepanel
```

Or in one line: `curl -fsSL https://raw.githubusercontent.com/qrussell/redstonepanel/main/install.sh | sudo sh`

Then open **http://&lt;server&gt;:8080/** and sign in with a Linux account in the `sudo` group.

To check the repository key before trusting it, `gpg --show-keys /usr/share/keyrings/qrussell-repo.gpg` should show the fingerprint `9994A9EB39EB3C101C949FB2012BA14E0FE3A355`.

Prefer not to add a repository? Download `redstonepanel_1.16.2_all.deb` below and run `sudo apt install ./redstonepanel_1.16.2_all.deb`. You then install each new version the same way.

The [user manual](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md) walks through every feature, with screenshots.

## Upgrading

If you use the qrussell-repo repository:

```bash
sudo apt update && sudo apt upgrade
```

New versions reach the repository within a few hours of their release. Otherwise, install the new .deb as above.

Running servers keep running through the upgrade.
