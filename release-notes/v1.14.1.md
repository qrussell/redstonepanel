The panel now knows about Bedrock's NetherNet transport: it opens the right firewall ports for it, checks them on the dashboard, and no longer offers Phantom for servers it can't help.

## Fixed

- **Firewall rules for NetherNet servers.** A Bedrock server with `transport=nethernet` gets TCP on its `server-port` (signaling), UDP on its `server-udp-ports` (gameplay) and UDP **7551** (LAN discovery, shared by every NetherNet server on the machine). Before, the panel only opened UDP on `server-port`, so consoles couldn't find or join it.
- **Ports follow the server's settings.** Changing the port or transport in Configuration (form or raw editor) or applying a template opens the new ports and closes the old ones. Removing a server closes only ports no other server still needs.
- **The dashboard checks every port a server needs** and lists the missing ones under **Needs attention**, with the `sudo ufw allow` command to open them. A closed 7551 is reported as consoles not finding the server under LAN Games. The check is current as soon as the panel changes a rule.
- **Phantom and NetherNet.** The Phantom card no longer offers Install for a NetherNet server and says why: Phantom only relays the older RakNet protocol, and a NetherNet server announces itself to consoles on its own. A NetherNet server on port 19132 no longer blocks Phantoms for other servers, since its 19132 is TCP.

Servers that already exist aren't changed by the upgrade. If one is missing a port, the dashboard says which and how to open it.

## Installing

RedstonePanel runs on **Ubuntu 24.04 and 25.04**. The easiest way to install it, and to get every later version with `apt upgrade`, is the signed **qrussell-repo** apt repository:

```bash
sudo apt install -y curl ca-certificates
curl -fsSL https://qrussell.github.io/qrussell-repo/deb/qrussell-repo.gpg | sudo tee /usr/share/keyrings/qrussell-repo.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/qrussell-repo.gpg] https://qrussell.github.io/qrussell-repo/deb ./" | sudo tee /etc/apt/sources.list.d/qrussell.list
sudo apt update
sudo apt install redstonepanel
```

Then open **http://&lt;server&gt;:8080/** and sign in with a Linux account in the `sudo` group.

To check the repository key before trusting it, `gpg --show-keys /usr/share/keyrings/qrussell-repo.gpg` should show the fingerprint `9994A9EB39EB3C101C949FB2012BA14E0FE3A355`.

Prefer not to add a repository? Download `redstonepanel_1.14.1_all.deb` below and run `sudo apt install ./redstonepanel_1.14.1_all.deb`. You then install each new version the same way.

The [user guide](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md) walks through every feature, with screenshots.

## Upgrading

If you use the qrussell-repo repository:

```bash
sudo apt update && sudo apt upgrade
```

New versions reach the repository within a few hours of their release. Otherwise, install the new .deb as above.

Running servers keep running through the upgrade.
