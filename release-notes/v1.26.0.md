Sleep mode: a server nobody is playing on stops by itself and starts again when a player joins. Visitors of a join page can start a stopped server too.

## New

- **Sleep mode.** On a server's **Maintenance** tab, tick **Sleep when nobody is playing** and choose how many minutes (15 by default; or `sudo redstonepanel sleep NAME on 15`). When nobody has played for that long, the panel stops the server to free its memory and CPU, and listens on its port itself. A Java server shows **Sleeping: join to start it** in Minecraft's server list; a player who joins starts it and is asked to join again in about 30 seconds (a minute for modded servers). A Bedrock server starts on the first try to join, and the player joins again once it runs. Looking at the server list doesn't wake it. **☾ Sleep now** puts it to sleep straight away, **Stop** means stopped (joining doesn't start it), and the dashboard shows a sleeping server with a blue ☾. Works on Linux and Windows, on cluster nodes from the master, and is kept when a server moves to another node. See [Sleep mode](https://github.com/qrussell/redstonepanel/blob/v1.26.0/docs/guide/README.md#sleep-mode).

- **Start the server from its join page.** In a join page's settings, **Let visitors start the server** adds a **Start the server** button while the server is stopped; the page then shows it starting and tells visitors when they can join. It's off by default, the panel starts the server itself (no key in the browser), and a server can be started this way once every 2 minutes, 3 times an hour per visitor. See [Join pages](https://github.com/qrussell/redstonepanel/blob/v1.26.0/docs/guide/README.md#join-pages).

- **Start at boot and sleep mode together.** A server with sleep mode on is never started by the machine at boot: after a reboot it goes back to sleep if **Start at boot** is on, and stays stopped if it's off.

## Fixed

- **No false port alert after a start.** Right after a server started (or a sleeping one woke), the dashboard could say for up to three minutes that its port was held by "another program the system can't name". It now looks again before saying so.

## Upgrading an existing panel

Nothing to do: `apt upgrade`, **Update now**, or the new MSI as usual. Sleep mode is off for every server until you turn it on. To use it on a cluster node's servers, update that node to 1.26.0 too.

Tested: 1,280 unit tests, including new ones for sleep mode, the join page Start button and the port check; a sleep test with real servers (vanilla Java 1.21.11 with a real Minecraft client, Bedrock over RakNet and over NetherNet), covering waking, sleeping again, Stop, panel and machine restarts with Start at boot on and off, and the join page Start; the install tests on every supported system; and the cluster tests. Sleep mode was also tried with a real Bedrock client on a test panel.

## Installing on Windows

1. Download `RedstonePanel-1.26.0-x64.msi` below and open it. It isn't signed yet, so SmartScreen says **Windows protected your PC**: choose **More info**, then **Run anyway**. Its SHA-256 is in `RedstonePanel-1.26.0-x64.msi.sha256` next to it.
2. Choose where servers, backups and settings are kept. The default is `C:\ProgramData\RedstonePanel`, and the folder's name can't have a space in it.
3. Leave **Open RedstonePanel in my browser** ticked and click **Finish**, then choose your password for **admin**. Or sign in with your own Windows administrator account.

See [On Windows](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md#on-windows) in the manual.

## Installing

RedstonePanel runs on **Ubuntu 24.04, 26.04 and 26.10**, **Debian 13** and **64-bit Raspberry Pi OS** (Raspberry Pi 4 or 5), on x86-64 and ARM64. See [Supported systems](https://github.com/qrussell/redstonepanel#supported-systems). The easiest way to install it, and to get every later version with `apt upgrade`, is the signed **qrussell-repo** apt repository:

```bash
sudo apt install -y curl ca-certificates
curl -fsSL https://qrussell.github.io/qrussell-repo/deb/qrussell-repo.gpg | sudo tee /usr/share/keyrings/qrussell-repo.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/qrussell-repo.gpg] https://qrussell.github.io/qrussell-repo/deb ./" | sudo tee /etc/apt/sources.list.d/qrussell.list
sudo apt update
sudo apt install redstonepanel
```

Or in one line: `curl -fsSL https://raw.githubusercontent.com/qrussell/redstonepanel/main/install.sh | sudo sh`

Then open **http://&lt;server&gt;:8080/** and sign in with a Linux account in the `sudo` group.

To check the repository key before trusting it, `gpg --show-keys /usr/share/keyrings/qrussell-repo.gpg` should show the fingerprint `9994A9EB39EB3C101C949FB2012BA14E0FE3A355`.

Prefer not to add a repository? Download `redstonepanel_1.26.0_all.deb` below and run `sudo apt install ./redstonepanel_1.26.0_all.deb`. You then install each new version the same way.

The [user manual](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md) walks through every feature, with screenshots.

## Upgrading

If you use the qrussell-repo repository:

```bash
sudo apt update && sudo apt upgrade
```

New versions reach the repository within a few hours of their release. Otherwise, install the new .deb as above.

Running servers keep running through the upgrade.
