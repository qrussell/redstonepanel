Move a server to another machine in your cluster, or copy it, from the master's cluster page. Nothing is deleted until you say so.

## Added

- **Move a server between cluster members.** On the 🌐 Cluster page, admins get **Move…** for every server, on the master and on every node. Pick where it goes and the panel does the rest:
  1. the server stops and its whole folder is packed (world, server software, mods, settings);
  2. the master streams it to the other machine, which checks every byte against a SHA-256 checksum (no size limit);
  3. the other machine installs it under the same name and ports when they're free there (it tells you if it had to pick others), installs the Java it needs, carries over its memory, backup and restart schedules and Phantom, starts it and checks it keeps running;
  4. only then is it taken off the old machine. Its files stay there as a removed server marked **moved to …**, so you can restore it if anything is wrong.

  When you're happy, click **Delete the old copy** in the move's window (or 🗑 next to it under **New Server → Removed servers**) to free the space.
- **If anything fails, nothing changes.** A move that can't finish removes what it made on the new machine and starts the server where it was. While a move runs, the server can't be started on the old machine.
- **Copy a server**, to another member or to the same one, without stopping it: the world is saved first, as backups do. The copy gets its own name and port where needed, and you choose whether to start it. Schedules and Phantom stay with the original.
- **Templates between members.** In the template manager, copy one of the master's templates to a node, or copy a template a node made on its own panel to the master.
- A progress bar follows each move, and the console logs every step on both machines (`[MOVE] …`).

## Fixed

- Template names are shown safely in the template manager.

## Upgrading a cluster

Update the master and every node you want to move servers to or from. The cluster contract is now version 3. A node still on 1.15 keeps working as before, but the master won't offer it as a source or target for moves until it's updated.

What doesn't move: a server's older backups stay in `/var/backups/redstonepanel` on the old machine, and its player history stays there too.

## Installing

RedstonePanel runs on **Ubuntu 24.04 and 25.04**. The easiest way to install it, and to get every later version with `apt upgrade`, is the signed **qrussell-repo** apt repository:

```bash
sudo apt install -y curl ca-certificates
curl -fsSL https://qrussell.github.io/qrussell-repo/deb/qrussell-repo.gpg | sudo tee /usr/share/keyrings/qrussell-repo.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/qrussell-repo.gpg] https://qrussell.github.io/qrussell-repo/deb ./" | sudo tee /etc/apt/sources.list.d/qrussell.list
sudo apt update
sudo apt install redstonepanel
```

Or in one line: `curl -fsSL https://raw.githubusercontent.com/qrussell/redstonepanel/main/install.sh | sudo sh`

Then open **http://&lt;server&gt;:8080/** and sign in with a Linux account in the `sudo` group.

To check the repository key before trusting it, `gpg --show-keys /usr/share/keyrings/qrussell-repo.gpg` should show the fingerprint `9994A9EB39EB3C101C949FB2012BA14E0FE3A355`.

Prefer not to add a repository? Download `redstonepanel_1.16.0_all.deb` below and run `sudo apt install ./redstonepanel_1.16.0_all.deb`. You then install each new version the same way.

The [user manual](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md) walks through every feature, with screenshots.

## Upgrading

If you use the qrussell-repo repository:

```bash
sudo apt update && sudo apt upgrade
```

New versions reach the repository within a few hours of their release. Otherwise, install the new .deb as above.

Running servers keep running through the upgrade.
