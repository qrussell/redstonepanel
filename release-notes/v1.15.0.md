Manage every node's servers from the cluster master: every tab, new servers on any node, and real certificates for a master on the internet.

## Added

- **Every server, every tab, from the master.** On a cluster master, the sidebar lists each node's servers under the node's name. Opening one shows the same tabs as a server on the master: Overview, Live Chat, Configuration (with Whitelist & Access), Maintenance, Backups, World & Maps, Files, Mods, Java and Phantom. Downloads (backups, exports, files) and uploads (files, mods) work too. The 🌐 Cluster page gets an **Open** button for each server.
- **Rights follow the master's accounts.** An admin on the master acts as an admin on the nodes. A user on the master gets a user's rights there, so no file manager, Java or Phantom. Both panels log each change with the master user's name, for example `[CLUSTER] alex@Main panel: POST /api/servers/minecraft-java/whitelist/add`.
- **What a node never lets the master do:** see or change its users, settings or HTTPS, update the panel, remove the node from the cluster through a server tab, or erase a server's files. Uninstalling from the master keeps the world as a removed server that can be restored.
- **New Server → Where.** On a master you choose the panel to create the server on. A template is copied to that node first, ports are chosen there, and if the node is missing the Java the version needs, an admin can install it there. **Save as Template** on a node's server saves it as one of the master's templates. **Removed servers** in the same dialog follow the Where choice.
- **Real certificates for a master on the internet.** A cluster master can now use its own certificate (certbot or another you supply) for browsers. Browsers only ever talk to the master, so nodes can stay on private addresses with their cluster certificates. Switch under **Panel Settings → Connection**.
- **Nodes with a public certificate.** A panel that already uses its own certificate can join a cluster. The master reaches it by that name and checks it against the system's trust store instead of the cluster CA. You can change how a node is checked under **Panel Settings → Cluster**.
- **Automatic certificate renewal.** The master renews each node's cluster certificate, and its own, 30 days before it expires. A renewal that fails is shown on the node's row.
- **Nightly cluster backups.** **Panel Settings → Cluster → Nightly backups**, or `sudo redstonepanel cluster nightly on`, writes an encrypted cluster backup every night after 3:00 and keeps the last 7. The passphrase is stored on the master so this can run unattended. Download a copy now and then and keep it somewhere else.

- **Easier to find your way.** A one-line installer
  (`curl -fsSL https://raw.githubusercontent.com/qrussell/redstonepanel/main/install.sh | sudo sh`),
  a screenshot tour in the README, the user guide reworked into a
  [user manual](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md) with a
  "How do I…" index and new screenshots, and a
  [wiki](https://github.com/qrussell/redstonepanel/wiki) with installation, FAQ, what's new and
  the roadmap.

## Upgrading a cluster

Update the master and the nodes. The cluster contract is now version 2: a node still on 1.14 keeps showing up with start, stop and restart, and its group in the sidebar asks you to update it before you can manage its servers from the master.

## Installing

RedstonePanel runs on **Ubuntu 24.04 and 25.04**. The easiest way to install it, and to get every later version with `apt upgrade`, is the signed **qrussell-repo** apt repository:

```bash
sudo apt install -y curl ca-certificates
curl -fsSL https://qrussell.github.io/qrussell-repo/deb/qrussell-repo.gpg | sudo tee /usr/share/keyrings/qrussell-repo.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/qrussell-repo.gpg] https://qrussell.github.io/qrussell-repo/deb ./" | sudo tee /etc/apt/sources.list.d/qrussell.list
sudo apt update
sudo apt install redstonepanel
```

Then open **http://&lt;server&gt;:8080/** and sign in with a Linux account in the `sudo` group.

To check the repository key before trusting it, `gpg --show-keys /usr/share/keyrings/qrussell-repo.gpg` should show the fingerprint `9994A9EB39EB3C101C949FB2012BA14E0FE3A355`.

Prefer not to add a repository? Download `redstonepanel_1.15.0_all.deb` below and run `sudo apt install ./redstonepanel_1.15.0_all.deb`. You then install each new version the same way.

The [user guide](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md) walks through every feature, with screenshots.

## Upgrading

If you use the qrussell-repo repository:

```bash
sudo apt update && sudo apt upgrade
```

New versions reach the repository within a few hours of their release. Otherwise, install the new .deb as above.

Running servers keep running through the upgrade.
