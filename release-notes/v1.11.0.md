## Added

- **Dashboard.** With no server selected (after signing in, or with the new **📊 Dashboard** button), the panel shows:
  - **Needs attention**, only when something is wrong: a nearly full disk or memory, a failed or crash-looping server, a failed backup, a missing Java, a game port the firewall (ufw) blocks, a stopped Phantom proxy, a certificate expiring within 14 days, an unreachable cluster node, or a newer RedstonePanel in apt.
  - **CPU, memory, disk and network** use, with load average, swap and the free space where your servers live.
  - **Game servers**: state, uptime, CPU, memory, players online (Java with RCON), folder size, backups, and when the next backup and restart are due. Click a row to open the server.
  - **Host** details (Ubuntu release, kernel, uptime, time zone, addresses, panel version) and every **disk** that holds servers, backups or panel data.
  - **Supporting services**: the panel itself, installed Java versions and which servers use each, `screen`, the firewall, Phantom proxies, backup and restart timers, HTTPS and its certificate, notifications and the cluster.
  - It refreshes every 10 seconds while the page is open.
- **Cluster resources.** On a cluster master, the dashboard has a card per panel with its CPU, memory, disk, servers online and what needs attention, and the **🌐 Cluster** page shows each panel's CPU, memory and free disk under its name. Update your nodes to 1.11.0 too; older nodes show "Update RedstonePanel on this server."

## Notes

- Everything is read from `/proc`, disk statistics and `systemctl`; nothing new is installed. Folder sizes are measured in the background at low priority every 10 minutes.
- Visitors from a trusted local network who haven't signed in see the dashboard without addresses, versions, certificates or settings.
- The cluster master reads a node's dashboard through one new read-only route, `GET /api/host`. Like the rest of the cluster, it can't change anything on the node.

## Installing

RedstonePanel runs on **Ubuntu 24.04 and 25.04**. The easiest way to install it, and to get every later version with `apt upgrade`, is the signed **qrussell-repo** apt repository:

```bash
sudo apt install -y curl ca-certificates
curl -fsSL https://qrussell.github.io/qrussell-repo/deb/qrussell-repo.gpg | sudo tee /usr/share/keyrings/qrussell-repo.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/qrussell-repo.gpg] https://qrussell.github.io/qrussell-repo/deb ./" | sudo tee /etc/apt/sources.list.d/qrussell.list
sudo apt update
sudo apt install redstonepanel
```

Then open **http://&lt;server&gt;:8080/** and sign in with a Linux account in the `sudo` group.

To check the repository key before trusting it, `gpg --show-keys /usr/share/keyrings/qrussell-repo.gpg` should show the fingerprint `9994A9EB39EB3C101C949FB2012BA14E0FE3A355`.

Prefer not to add a repository? Download `redstonepanel_1.11.0_all.deb` below and run `sudo apt install ./redstonepanel_1.11.0_all.deb`. You then install each new version the same way.

The [user guide](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md) walks through every feature, with screenshots.

## Upgrading

If you use the qrussell-repo repository:

```bash
sudo apt update && sudo apt upgrade
```

New versions reach the repository within a few hours of their release. Otherwise, install the new .deb as above.

Running servers keep running through the upgrade.
