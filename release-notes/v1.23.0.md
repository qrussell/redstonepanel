RedstonePanel on Windows now does everything one computer needs: Bedrock servers, more loaders and modpacks, limits, off-site backups, updates from the panel and Windows sign-in. It is still labelled a preview until clusters arrive in 1.24.

## New on Windows

- **Bedrock servers.** The panel installs Mojang's Windows build of Bedrock Dedicated Server and keeps it up to date with **automatic Bedrock updates**, as on Linux. Its console, firewall rules and clean stop work the same. **Phantom** shows a server under LAN games for consoles.

- **Quilt, Forge and NeoForge servers, and modpacks** from Modrinth, a `.mrpack` or a CurseForge server pack. Their installers run as the new server's own Windows account, inside its own folder.

- **Hard memory and processor limits** under **Maintenance → Memory and limits**, and the performance history behind them. A server that reaches its memory limit stops with "ran out of memory" on Windows, and the crash card says it reached its limit.

- **Crash explanations for Windows causes:** a port Hyper-V, WSL or Docker Desktop reserved, a file locked by another program such as antivirus or OneDrive, a file the server's account may not change, and a missing Visual C++ runtime.

- **Off-site backup copies** to SSH storage (a NAS or another computer, through Windows' own OpenSSH client) and to S3 storage such as Backblaze B2.

- **Update now** updates the panel. It downloads the newest `RedstonePanel-x.y.z-x64.msi` from the GitHub release, refuses it unless its SHA-256 matches, and runs the Windows installer. Game servers stop for about a minute while the files are replaced, then start again.

- **Sign in with a Windows account.** An account in the **Administrators** group signs in as an admin. To let another account in, add it to a local group named **RedstonePanel**. Panel accounts work as before.

- **Port forwarding and Needs attention know Windows.** The Port forwarding page names your router and the ports to forward. Needs attention warns when a server's port is inside a range Hyper-V, WSL or Docker reserved, when the PC is set to go to sleep while plugged in, and when Windows Update is waiting to restart the PC.

- **No terminal on Windows, by design.** A Windows panel usually runs on the computer its owner sits at, and a command prompt is one click away there. Clusters and SFTP come to Windows in 1.24.

## Fixed

- **With HTTPS on, the Windows firewall now opens the HTTPS port too.** Before, the panel's firewall rule opened only port 8080. The installer and **Panel Settings** now keep the rule in step with the panel's ports.

- **A new Bedrock server skips ports another program holds.** If something outside the panel already uses UDP 19132 or 19133, such as Geyser in a server the panel doesn't manage, a new Bedrock server takes the next free pair. The panel also reads Geyser's port on NeoForge and BungeeCord now. This applies on Linux too.

## Upgrading an existing panel

- **Windows:** download `RedstonePanel-1.23.0-x64.msi` below and run it once. Your servers, worlds and settings stay. The 1.22 preview can't update itself, so this first update is by hand. From 1.23 on, **Update now** on the dashboard does it.
- **Linux:** nothing to do.

## Installing on Windows

1. Download `RedstonePanel-1.23.0-x64.msi` below and open it. It isn't signed yet, so SmartScreen says **Windows protected your PC**: choose **More info**, then **Run anyway**. Its SHA-256 is in `RedstonePanel-1.23.0-x64.msi.sha256` next to it.
2. Choose where servers, backups and settings are kept. The default is `C:\ProgramData\RedstonePanel`, and the folder's name can't have a space in it.
3. Open **http://localhost:8080** and sign in as **admin** with the password in `first-sign-in.txt` in that folder (open it as an administrator). Or sign in with your own Windows administrator account. Change the admin password under **Users**, then delete the file.

See [On Windows (preview)](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md#on-windows-preview) in the manual.

Tested: GitHub's Windows Server 2022 and 2025 machines install the MSI and run the Windows install test. It covers a Java server end to end, then limits, S3 off-site copies, join pages, a Bedrock server with its console, firewall, clean stop and update check, Phantom, a Forge server, the servers folder, Found servers and Windows account sign-in. Then it installs over itself and removes it. On Quentin's own Windows PC the same test passed 96 of 104 checks as administrator. The failures were mistakes in the test, which are fixed: it assumed the servers folder, and it stopped every Java process. That run also found the HTTPS firewall rule and the router address, both fixed here. The 1,065 unit tests pass, and the Linux install and cluster tests pass on every supported system.

## Installing

RedstonePanel runs on **Ubuntu 24.04, 26.04 and 26.10**, **Debian 13** and **64-bit Raspberry Pi OS** (Raspberry Pi 4 or 5), on x86-64 and ARM64. See [Supported systems](https://github.com/qrussell/redstonepanel#supported-systems). The easiest way to install it, and to get every later version with `apt upgrade`, is the signed **qrussell-repo** apt repository:

```bash
sudo apt install -y curl ca-certificates
curl -fsSL https://qrussell.github.io/qrussell-repo/deb/qrussell-repo.gpg | sudo tee /usr/share/keyrings/qrussell-repo.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/qrussell-repo.gpg] https://qrussell.github.io/qrussell-repo/deb ./" | sudo tee /etc/apt/sources.list.d/qrussell.list
sudo apt update
sudo apt install redstonepanel
```

Or in one line: `curl -fsSL https://raw.githubusercontent.com/qrussell/redstonepanel/main/install.sh | sudo sh`

Then open **http://&lt;server&gt;:8080/** and sign in with a Linux account in the `sudo` group.

To check the repository key before trusting it, `gpg --show-keys /usr/share/keyrings/qrussell-repo.gpg` should show the fingerprint `9994A9EB39EB3C101C949FB2012BA14E0FE3A355`.

Prefer not to add a repository? Download `redstonepanel_1.23.0_all.deb` below and run `sudo apt install ./redstonepanel_1.23.0_all.deb`. You then install each new version the same way.

The [user manual](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md) walks through every feature, with screenshots.

## Upgrading

If you use the qrussell-repo repository:

```bash
sudo apt update && sudo apt upgrade
```

New versions reach the repository within a few hours of their release. Otherwise, install the new .deb as above.

Running servers keep running through the upgrade.
