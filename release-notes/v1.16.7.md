Two-factor sign-in: a code from your phone after your password, with recovery codes for a lost phone.

## New

- **Two-factor sign-in.** Click **🔑 Password**, then **Set Up Two-Factor**, and scan the QR code with any authenticator app (Google Authenticator, Microsoft Authenticator, Aegis, 1Password, Bitwarden and so on), or type the key under it. From then on the sign-in page asks for the six-digit code after your password. It works for panel accounts and Linux accounts alike.
- **Ten recovery codes**, shown once at setup, each signing you in once if you lose your phone. Copy or download them, and make new ones later under **🔑 Password**.
- **Require two-factor for admins** in **🛡️ Settings → Sign-in** (off by default). An admin who hasn't set it up is taken straight to setup after signing in and can't do anything else until they have. The panel won't turn it on until your own account has two-factor.
- **Reset two-factor** under **👥 Users** for someone who lost their phone, and `sudo redstonepanel reset-2fa NAME` on the server for any account, Linux ones included.
- **The 🔑 Password button now shows for Linux accounts** too, for two-factor (their password is still changed with `passwd`).

## Changed

- **Turning two-factor on signs out your other browsers**; they sign in again with a code.
- **Wrong codes count towards the sign-in limit** (five failures in ten minutes), and entering the right password again doesn't reset that count while a code is still needed.
- Trusted-network access is unchanged (it never gives admin), and cluster nodes are unaffected.

Tested: 27 new unit tests, every QR code size checked with an independent decoder, and the whole flow (setup, sign-in with a code, a wrong code, a recovery code, an admin made to set it up) in a real browser.

## Upgrading an existing panel

Nothing to do: two-factor is off until each person sets it up. Reload the panel in your browser after the upgrade. If you'd like every admin to use it, set up your own first, then turn on **Require two-factor for admins**.

## Installing

RedstonePanel runs on **Ubuntu 24.04 and 25.04**. The easiest way to install it, and to get every later version with `apt upgrade`, is the signed **qrussell-repo** apt repository:

```bash
sudo apt install -y curl ca-certificates
curl -fsSL https://qrussell.github.io/qrussell-repo/deb/qrussell-repo.gpg | sudo tee /usr/share/keyrings/qrussell-repo.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/qrussell-repo.gpg] https://qrussell.github.io/qrussell-repo/deb ./" | sudo tee /etc/apt/sources.list.d/qrussell.list
sudo apt update
sudo apt install redstonepanel
```

Or in one line: `curl -fsSL https://raw.githubusercontent.com/qrussell/redstonepanel/main/install.sh | sudo sh`

Then open **http://&lt;server&gt;:8080/** and sign in with a Linux account in the `sudo` group.

To check the repository key before trusting it, `gpg --show-keys /usr/share/keyrings/qrussell-repo.gpg` should show the fingerprint `9994A9EB39EB3C101C949FB2012BA14E0FE3A355`.

Prefer not to add a repository? Download `redstonepanel_1.16.7_all.deb` below and run `sudo apt install ./redstonepanel_1.16.7_all.deb`. You then install each new version the same way.

The [user manual](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md) walks through every feature, with screenshots.

## Upgrading

If you use the qrussell-repo repository:

```bash
sudo apt update && sudo apt upgrade
```

New versions reach the repository within a few hours of their release. Otherwise, install the new .deb as above.

Running servers keep running through the upgrade.
