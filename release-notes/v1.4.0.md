Shows why Bedrock players can't connect, including Phantom proxies the panel didn't install.

## Added

- **Bedrock connection checks on the Overview tab.** Each one explains the problem and the setting that fixes it:
  - *Transport rejected*: Bedrock 1.26.x accepts only NetherNet. With `transport=raknet` the server starts, answers pings, and logs a `TRANSPORT TYPE ERROR`, but nobody can join. The panel reads this from the log of the server's last start.
  - *Not accepting clients*: a NetherNet server that finished starting without opening its TCP port (no `Accepting clients on …` in its log).
  - *`server-udp-ports` with a public address*: on 1.26.63.1, the documented form `203.0.113.7:19141:19141` silently stops the server from accepting clients. The panel suggests the plain form (`19141`), which works.
- **Phantom proxy detection.** Phantom services set up next to a Bedrock server are found whatever their name, and shown with their state, target and ports. A running one is flagged when it breaks the server: Phantom always takes UDP 19132, and pointed at `127.0.0.1:19132` it forwards to itself and answers every player with "Server offline". The note includes the command to stop it.
- **NetherNet ports at a glance**: the TCP signaling port players connect to and the UDP gameplay ports, which both need forwarding for players outside your network.
- The server list marks a server with ⚠ when players can't connect or a running Phantom interferes.

## Upgrading

```bash
sudo apt install ./redstonepanel_1.4.0_all.deb
```

Or `sudo apt update && sudo apt upgrade` if you use the qrussell-repo apt repository.

## Under the hood

- New unit tests for Phantom detection and the Bedrock log and `server-udp-ports` checks, built from real 1.26.63.1 logs.
- Checked read-only against two live hosts running Bedrock 1.26.63.1 with NetherNet, each with a disabled Phantom service.
