Run Paper and Fabric servers, on the Minecraft version you choose, each with the Java it needs.

## Added

- **Paper and Fabric.** **➕ New Server** now asks for a **Server Type** when you pick Java:
  - **Vanilla (Mojang)**, as before.
  - **Paper (plugins)**: the newest stable Paper build. Put plugins in the server's `plugins` folder.
  - **Fabric (mods)**: Fabric's server launcher with the newest stable loader. Put mods in the server's `mods` folder.
- **Choose the Minecraft version.** **Newest** is the default; any release can be picked instead, to match your players or your plugins and mods.
- **The right Java for each server.** Minecraft 26.1 and newer needs Java 25, 1.20.5 to 1.21.11 Java 21, 1.18 to 1.20.4 Java 17, 1.17 Java 16 (17 runs it) and older versions Java 8. The panel runs each server with the matching Java from `/usr/lib/jvm`, or the closest newer one, and says which package to install when none is new enough. For example, for a 1.21 server:
  ```bash
  sudo apt install openjdk-21-jre-headless
  ```
  The New Server dialog shows this before you deploy, and nothing is downloaded until the Java is there.
- **Update to a chosen version.** The Maintenance tab's **Update Server** lets a Java server stay on its Minecraft version (getting the newest build) or move to a newer one. Older versions aren't offered: a world opened by a newer version can't go back.

## Changed

- Updating a Java server downloads the new jar **before** stopping the server, so a failed download leaves it running as it was. Update errors now show in the panel instead of only in the console.
- Vanilla and Paper downloads are checked against their published checksums.
- The server list and Overview show the type, for example "Paper 1.21.10".

## Notes

- Existing servers keep running as they are. Their units still use `/usr/bin/java` until they're next updated, which points them at the Java their version needs.
- Servers made before 1.9 are recognised from their jar, so a Paper or Fabric server you set up by hand shows as such.
- Switching an existing server from one type to another (say vanilla to Paper) isn't offered yet.

## Installing

RedstonePanel runs on **Ubuntu 24.04 and 25.04**. The easiest way to install it, and to get every later version with `apt upgrade`, is the signed **qrussell-repo** apt repository:

```bash
sudo apt install -y curl ca-certificates
curl -fsSL https://qrussell.github.io/qrussell-repo/deb/qrussell-repo.gpg | sudo tee /usr/share/keyrings/qrussell-repo.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/qrussell-repo.gpg] https://qrussell.github.io/qrussell-repo/deb ./" | sudo tee /etc/apt/sources.list.d/qrussell.list
sudo apt update
sudo apt install redstonepanel
```

Then open **http://&lt;server&gt;:8080/** and sign in with a Linux account in the `sudo` group.

To check the repository key before trusting it, `gpg --show-keys /usr/share/keyrings/qrussell-repo.gpg` should show the fingerprint `9994A9EB39EB3C101C949FB2012BA14E0FE3A355`.

Prefer not to add a repository? Download `redstonepanel_1.9.0_all.deb` below and run `sudo apt install ./redstonepanel_1.9.0_all.deb`. You then install each new version the same way.

The [user guide](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md) walks through every feature, with screenshots.

## Upgrading

If you use the qrussell-repo repository:

```bash
sudo apt update && sudo apt upgrade
```

New versions reach the repository within a few hours of their release. Otherwise, install the new .deb as above.

Running servers keep running through the upgrade.
