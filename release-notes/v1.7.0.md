Back up your worlds on a schedule, and put one back with a click.

## Added

- **Scheduled backups.** Each server has a new **Backups** tab. Turn on **Automatic backups**, pick how often (every hour, every 6 or 12 hours, every day, or every Sunday) and at what time, and how many to keep. The schedule is a systemd timer (`redstonepanel-backup@<server>.timer`), so backups happen even while the panel is stopped, and one missed while the machine was off runs at the next boot.
  - The time is the server's clock, and the form shows its time zone. A server on UTC runs a "04:00" backup at 04:00 UTC, whatever your browser's time.
  - Only scheduled backups are pruned to the number you keep. Manual backups and the ones taken before a restore stay until you delete them.
- **Consistent copies of running servers.** Java servers stop writing to disk while the files are copied (`save-off`, `save-all flush`, then `save-on` over RCON). Bedrock servers do the same with `save hold`, `save query` and `save resume`. A Java server without RCON is copied while it runs, and the panel says so: open its **Live Chat** tab once to set RCON up.
- **Back up now, download and delete** from the same tab.
- **Restore a backup** (admins). The server is stopped, its world is replaced with the one in the backup, and it starts again. The world it replaces is saved first as a **Before restore** backup, so a restore can be undone.
- **From the command line:** `sudo redstonepanel backup NAME` takes a backup.

## Where backups live

Backups are `.tar.gz` files in `/var/backups/redstonepanel/<server>/`, readable only by root. They hold the server's folder (worlds, `server.properties`, allowlist, ops and so on) without what can be downloaded again (`server.jar`, `bedrock_server`, Bedrock's own packs) or logs, so they stay small.

They live outside `/opt`, so uninstalling a server, even with its files, doesn't delete its backups. Uninstalling removes the server's backup timer; restoring the server (**New Server → Removed servers**) brings its schedule back.

Copy that folder to another machine or disk if you want backups that survive losing this one.

## Installing

RedstonePanel runs on **Ubuntu 24.04 and 25.04**. The easiest way to install it, and to get every later version with `apt upgrade`, is the signed **qrussell-repo** apt repository:

```bash
sudo apt install -y curl ca-certificates
curl -fsSL https://qrussell.github.io/qrussell-repo/deb/qrussell-repo.gpg | sudo tee /usr/share/keyrings/qrussell-repo.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/qrussell-repo.gpg] https://qrussell.github.io/qrussell-repo/deb ./" | sudo tee /etc/apt/sources.list.d/qrussell.list
sudo apt update
sudo apt install redstonepanel
```

Then open **http://&lt;server&gt;:8080/** and sign in with a Linux account in the `sudo` group.

To check the repository key before trusting it, `gpg --show-keys /usr/share/keyrings/qrussell-repo.gpg` should show the fingerprint `9994A9EB39EB3C101C949FB2012BA14E0FE3A355`.

Prefer not to add a repository? Download `redstonepanel_1.7.0_all.deb` below and run `sudo apt install ./redstonepanel_1.7.0_all.deb`. You then install each new version the same way.

## Upgrading

If you use the qrussell-repo repository:

```bash
sudo apt update && sudo apt upgrade
```

New versions reach the repository within a few hours of their release. Otherwise, install the new .deb as above. Nothing changes for running servers, and no backups are scheduled until you turn them on.
