Groundwork for RedstonePanel on Windows. Nothing changes on screen, and there is nothing to do after upgrading.

## New

- **The first step towards a Windows version.** RedstonePanel was written for Ubuntu, and it ran `systemctl`, `ufw`, `screen`, `apt` and `openssl` from more than two dozen files. All of that, and every system folder the panel uses, now sits behind one internal package (`core/platform`), so a Windows side can be added next to the Linux one without touching each feature. See the [roadmap](https://github.com/qrussell/redstonepanel/blob/main/docs/wiki/Roadmap.md): 1.22 is planned as the Windows preview.
- **The same commands as before.** On Linux the panel runs what it always ran, with the same arguments. Servers, backups, schedules, the firewall and clusters work as they did in 1.20.
- **For contributors:** new panel code calls `core.platform` instead of starting a system program or typing out a system path, and a test fails the build otherwise. A pretend system lets new tests run without touching the machine. The [design notes](https://github.com/qrussell/redstonepanel/blob/main/docs/design/platform.md) explain how to add a call.

Tested: the 784 unit tests from before pass unchanged, plus 20 new ones; the install test and every feature test pass unchanged on Ubuntu 24.04, 26.04 and 26.10 and Debian 13, on x86-64 and ARM64.

## Upgrading an existing panel

- Nothing to do. In a cluster, upgrade the nodes when it suits you; 1.21 and 1.20 members work together.

## Installing

RedstonePanel runs on **Ubuntu 24.04, 26.04 and 26.10**, **Debian 13** and **64-bit Raspberry Pi OS** (Raspberry Pi 4 or 5), on x86-64 and ARM64. See [Supported systems](https://github.com/qrussell/redstonepanel#supported-systems). The easiest way to install it, and to get every later version with `apt upgrade`, is the signed **qrussell-repo** apt repository:

```bash
sudo apt install -y curl ca-certificates
curl -fsSL https://qrussell.github.io/qrussell-repo/deb/qrussell-repo.gpg | sudo tee /usr/share/keyrings/qrussell-repo.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/qrussell-repo.gpg] https://qrussell.github.io/qrussell-repo/deb ./" | sudo tee /etc/apt/sources.list.d/qrussell.list
sudo apt update
sudo apt install redstonepanel
```

Or in one line: `curl -fsSL https://raw.githubusercontent.com/qrussell/redstonepanel/main/install.sh | sudo sh`

Then open **http://&lt;server&gt;:8080/** and sign in with a Linux account in the `sudo` group.

To check the repository key before trusting it, `gpg --show-keys /usr/share/keyrings/qrussell-repo.gpg` should show the fingerprint `9994A9EB39EB3C101C949FB2012BA14E0FE3A355`.

Prefer not to add a repository? Download `redstonepanel_1.21.0_all.deb` below and run `sudo apt install ./redstonepanel_1.21.0_all.deb`. You then install each new version the same way.

The [user manual](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md) walks through every feature, with screenshots.

## Upgrading

If you use the qrussell-repo repository:

```bash
sudo apt update && sudo apt upgrade
```

New versions reach the repository within a few hours of their release. Otherwise, install the new .deb as above.

Running servers keep running through the upgrade.
