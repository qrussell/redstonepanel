A security release: fixes for problems found by GitHub code scanning, and the panel no longer follows links that a game server leaves in its own folder.

## Fixed

- **Player names are checked before they reach a Bedrock console.** On **Configuration → Players**, a Bedrock player's name could carry a line break into the server's console when the panel fell back to asking the server for the player's Xbox ID, and that fallback ran the server as root. Names and IDs are now checked like the whitelist's, and the fallback runs the server as the `minecraft` account.
- **The panel works in server folders with the game account's rights.** The panel runs as root, but a server's folder belongs to the `minecraft` account, and the server or a plugin can put a link there (for example `server.properties` pointing at a system file). Settings, operators, the whitelist, player roles, server and world downloads, renaming a world, Live Chat, installs, updates and backup restores could follow such a link with root's rights. They now work with the `minecraft` account's rights, so a link only reaches what the server itself could reach, and downloads leave links out.
- **A world outside the server folder is refused.** A `level-name` such as `../../etc` is no longer downloaded or renamed, and a backup's world name must stay inside the server folder.
- **Unknown server names are refused up front.** Every server page and API call answers "No Minecraft server by that name" before doing anything else when the name isn't one of the panel's servers.
- **Java players keep their UUID** on Configuration → Players (a slip in the first fix above, caught before release).
- The website's demo console escapes what it shows.

## Upgrading an existing panel

Nothing to do. On its first start, 1.21.8 hands any files it wrote in server folders as root before to the `minecraft` account, so it can keep changing them. If the panel ever can't open a file in a server folder (a file owned by another account, or a link to somewhere outside the folder), it now says so instead of following it, and logs it as `[SECURITY]`.

To report a security problem, see [SECURITY.md](https://github.com/qrussell/redstonepanel/blob/main/SECURITY.md).

Tested: the unit tests, and the .deb installed in systemd containers on Ubuntu 24.04: a new test plants links in a server folder as the `minecraft` account and checks that no panel action reads or changes a root-only file through them (27 checks, 16 of which fail on 1.21.7), plus the install, Bedrock update, found servers, crash and move tests.

## Installing

RedstonePanel runs on **Ubuntu 24.04, 26.04 and 26.10**, **Debian 13** and **64-bit Raspberry Pi OS** (Raspberry Pi 4 or 5), on x86-64 and ARM64. See [Supported systems](https://github.com/qrussell/redstonepanel#supported-systems). The easiest way to install it, and to get every later version with `apt upgrade`, is the signed **qrussell-repo** apt repository:

```bash
sudo apt install -y curl ca-certificates
curl -fsSL https://qrussell.github.io/qrussell-repo/deb/qrussell-repo.gpg | sudo tee /usr/share/keyrings/qrussell-repo.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/qrussell-repo.gpg] https://qrussell.github.io/qrussell-repo/deb ./" | sudo tee /etc/apt/sources.list.d/qrussell.list
sudo apt update
sudo apt install redstonepanel
```

Or in one line: `curl -fsSL https://raw.githubusercontent.com/qrussell/redstonepanel/main/install.sh | sudo sh`

Then open **http://&lt;server&gt;:8080/** and sign in with a Linux account in the `sudo` group.

To check the repository key before trusting it, `gpg --show-keys /usr/share/keyrings/qrussell-repo.gpg` should show the fingerprint `9994A9EB39EB3C101C949FB2012BA14E0FE3A355`.

Prefer not to add a repository? Download `redstonepanel_1.21.8_all.deb` below and run `sudo apt install ./redstonepanel_1.21.8_all.deb`. You then install each new version the same way.

The [user manual](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md) walks through every feature, with screenshots.

## Upgrading

If you use the qrussell-repo repository:

```bash
sudo apt update && sudo apt upgrade
```

New versions reach the repository within a few hours of their release. Otherwise, install the new .deb as above.

Running servers keep running through the upgrade.
