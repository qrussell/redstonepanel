API tokens for scripts and bots, a Start at boot switch for each server, and one click from the master into a node's own panel. Windows panels can update themselves again.

## New

- **API tokens.** Give a script or a Discord bot its own key: **Panel Settings → API tokens**, or `sudo redstonepanel token create`. You choose the servers (every server, or chosen ones, including servers on cluster nodes), what it may do (the same permissions as a helper account) and when it expires. A token is never an admin: it can't manage users or settings, create or delete servers, open the terminal or change a password. It's shown once, can be revoked at once, and everything it changes is in the panel log as `token:NAME`. Scripts send it as `Authorization: Bearer rpa_...`; every route is described at `/docs` on your panel. See [API tokens](https://github.com/qrussell/redstonepanel/blob/v1.25.0/docs/guide/README.md#api-tokens).

- **Start at boot.** A switch at the top of each server's **Maintenance** tab (and `redstonepanel boot NAME on|off`). Turn it off for a server you only play now and then, and it stays stopped after the machine restarts until someone clicks **Start**. On Linux it enables or disables the server's service; on Windows it sets the service to Automatic or Manual. Your choice is kept through restores, reinstalls and moves to another node. See [Start at boot](https://github.com/qrussell/redstonepanel/blob/v1.25.0/docs/guide/README.md#start-at-boot).

- **Open dashboard, signed in.** On the master's **Cluster** page, an admin's **Open dashboard ↗** opens a node's own panel already signed in, so you can reach its Users, Settings and **Update now** without an account on that machine. The link works once and for one minute, the sign-in ends if the node leaves the cluster or gets a new master, and each node can turn it off under **Settings → Cluster → Let the master's admins sign in here**. See [Accounts in a cluster](https://github.com/qrussell/redstonepanel/blob/v1.25.0/docs/guide/README.md#accounts-in-a-cluster).

## Fixed

- **Update now works on Windows again.** On Windows the dashboard's **Update now** downloaded and checked the new installer, then stopped: the PowerShell that runs the installer was started without a console window, and it quits straight away without one. The dashboard kept showing the update as running. The installer now runs as a one-off Task Scheduler task as the system account.

## Upgrading an existing panel

**Linux:** nothing to do; `apt upgrade` or **Update now** as usual.

**Windows panels on 1.24.0 or 1.24.1** still have the broken **Update now**, so install 1.25.0 by hand once: run `RedstonePanel-1.25.0-x64.msi` below. If you already clicked **Update now**, an older installer is downloaded; run the new one instead.

From 1.25.0 on, **Update now** works. Update every cluster member to use **Open dashboard** and API tokens on node servers: both need the node on 1.25.0.

Tested: 1,235 unit tests, including new ones for API tokens, Start at boot, the master sign-in and the Windows installer task; the install test on Ubuntu 24.04 (tokens and Start at boot from the page and the command line); and the cluster test with a master and two nodes (Open dashboard, once-only links, the node's switch, and a new master ending the old one's sign-ins).

## Installing on Windows

1. Download `RedstonePanel-1.25.0-x64.msi` below and open it. It isn't signed yet, so SmartScreen says **Windows protected your PC**: choose **More info**, then **Run anyway**. Its SHA-256 is in `RedstonePanel-1.25.0-x64.msi.sha256` next to it.
2. Choose where servers, backups and settings are kept. The default is `C:\ProgramData\RedstonePanel`, and the folder's name can't have a space in it.
3. Leave **Open RedstonePanel in my browser** ticked and click **Finish**, then choose your password for **admin**. Or sign in with your own Windows administrator account.

See [On Windows](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md#on-windows) in the manual.

## Installing

RedstonePanel runs on **Ubuntu 24.04, 26.04 and 26.10**, **Debian 13** and **64-bit Raspberry Pi OS** (Raspberry Pi 4 or 5), on x86-64 and ARM64. See [Supported systems](https://github.com/qrussell/redstonepanel#supported-systems). The easiest way to install it, and to get every later version with `apt upgrade`, is the signed **qrussell-repo** apt repository:

```bash
sudo apt install -y curl ca-certificates
curl -fsSL https://qrussell.github.io/qrussell-repo/deb/qrussell-repo.gpg | sudo tee /usr/share/keyrings/qrussell-repo.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/qrussell-repo.gpg] https://qrussell.github.io/qrussell-repo/deb ./" | sudo tee /etc/apt/sources.list.d/qrussell.list
sudo apt update
sudo apt install redstonepanel
```

Or in one line: `curl -fsSL https://raw.githubusercontent.com/qrussell/redstonepanel/main/install.sh | sudo sh`

Then open **http://&lt;server&gt;:8080/** and sign in with a Linux account in the `sudo` group.

To check the repository key before trusting it, `gpg --show-keys /usr/share/keyrings/qrussell-repo.gpg` should show the fingerprint `9994A9EB39EB3C101C949FB2012BA14E0FE3A355`.

Prefer not to add a repository? Download `redstonepanel_1.25.0_all.deb` below and run `sudo apt install ./redstonepanel_1.25.0_all.deb`. You then install each new version the same way.

The [user manual](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md) walks through every feature, with screenshots.

## Upgrading

If you use the qrussell-repo repository:

```bash
sudo apt update && sudo apt upgrade
```

New versions reach the repository within a few hours of their release. Otherwise, install the new .deb as above.

Running servers keep running through the upgrade.
