Know when a server crashes, restart servers on a schedule, and crashed Bedrock servers now come back by themselves.

## Added

- **Notifications.** **Panel Settings → Notifications** (admins) sends a message to a Discord channel, or to any web address that accepts a JSON POST, when something happens. Pick the events: a server crashed, started or stopped, a scheduled restart, a backup finished or failed. By default only crashes, failed backups and scheduled restarts are sent.
  - **Crashes are reported even while the panel is stopped.** The package adds a small systemd file for every `minecraft-*.service` whose start and stop hooks send the message, so it covers servers you made with earlier versions too.
  - A server stuck crashing sends one "crashed" message every 5 minutes, not one per crash.
  - The webhook URL lets anyone post in your channel, so it is stored readable only by root and the panel never shows it again (only its host and last few characters).
  - **Send a test** in the panel, or `sudo redstonepanel notify-test`.
  - In Discord: the channel's settings → **Integrations** → **Webhooks** → **New Webhook** → **Copy Webhook URL**.
- **Scheduled restarts.** Each server's **Maintenance** tab can restart it every day, every 6 or 12 hours, or every Sunday, at a time you pick (the server's clock). Players are warned in chat first ("Server restarts in 5 minutes", then 1 minute and 10 seconds before), and the restart happens at the time shown.
  - A server you stopped stays stopped, and a restart waits for a running backup of the same server.
  - Java servers are warned over RCON: open the **Live Chat** tab once so the panel sets it up. Without RCON the restart still happens on time, without a warning.
  - Like backups, restarts are systemd timers (`redstonepanel-restart@<server>.timer`), so they happen while the panel is stopped.
- **Coloured console.** Errors and crashes are red, warnings yellow, backups and restarts blue, sign-ins and settings purple, and the commands the panel runs grey.
- New commands: `redstonepanel restart-server NAME` and `redstonepanel notify-test`.

## Fixed

- **A crashed Bedrock server is started again.** Bedrock runs inside `screen`, which exits normally when the game dies, so systemd never noticed a Bedrock crash and the server stayed down until someone started it. Now a Bedrock server that stops without being asked, and without its own "Quit correctly", is treated as crashed and started again after 20 seconds, as Java servers already were. A `stop` typed in its console still stops it.
- **Stopping a Java server no longer leaves it "failed"** in `systemctl status`. Java exits with code 143 when stopped; that now counts as a clean stop.
- **Dark mode:** the dashboard's right side was white when no server was selected, and the **New Server** dialog's title was nearly invisible.

## Installing

RedstonePanel runs on **Ubuntu 24.04 and 25.04**. The easiest way to install it, and to get every later version with `apt upgrade`, is the signed **qrussell-repo** apt repository:

```bash
sudo apt install -y curl ca-certificates
curl -fsSL https://qrussell.github.io/qrussell-repo/deb/qrussell-repo.gpg | sudo tee /usr/share/keyrings/qrussell-repo.gpg >/dev/null
echo "deb [signed-by=/usr/share/keyrings/qrussell-repo.gpg] https://qrussell.github.io/qrussell-repo/deb ./" | sudo tee /etc/apt/sources.list.d/qrussell.list
sudo apt update
sudo apt install redstonepanel
```

Then open **http://&lt;server&gt;:8080/** and sign in with a Linux account in the `sudo` group.

To check the repository key before trusting it, `gpg --show-keys /usr/share/keyrings/qrussell-repo.gpg` should show the fingerprint `9994A9EB39EB3C101C949FB2012BA14E0FE3A355`.

Prefer not to add a repository? Download `redstonepanel_1.8.0_all.deb` below and run `sudo apt install ./redstonepanel_1.8.0_all.deb`. You then install each new version the same way.

The [user guide](https://github.com/qrussell/redstonepanel/blob/main/docs/guide/README.md) walks through every feature, with screenshots.

## Upgrading

If you use the qrussell-repo repository:

```bash
sudo apt update && sudo apt upgrade
```

New versions reach the repository within a few hours of their release. Otherwise, install the new .deb as above.

Running servers keep running through the upgrade, and the crash detection (including the Bedrock crash fix) covers them straight away, without a restart. No notifications are sent and no restarts are scheduled until you set them up.

## Under the hood

- New modules `core/notify.py` and `core/restarts.py`; the systemd drop-in is `/usr/lib/systemd/system/minecraft-.service.d/redstonepanel.conf`.
- A crash is a stop that systemd wasn't asked for (no job queued on the unit), rather than a non-zero exit code, since Bedrock's `screen` exits 1 on every normal stop.
- Tested with unit tests (`tests/test_notify.py`, `tests/test_restarts.py`) and end to end in a systemd container with real Java and Bedrock servers and a local webhook receiver.
